## 6. 阶段二：parse 设计

### 6.1 流程（双通道）

```
构建期（一次性、离线）：
  ① 打开 PDF → 逐页抽取，判定通道
     平均字符数 < 50 → 整册标记 need_vlm（无文本层，16 册 1277 页）
  ② 通道 A｜文本层：PyMuPDF 逐页抽取 + 拼音字体映射修复
        → 字符级精确、严格保持原文顺序（权威）
  ③ 通道 B｜VLM：渲染页图 → 多模态模型转录
        → 版式语义、表格、图注、扫描页（理解型）
  ④ 合并：按页记录 source；有文本层的页以 A 为正文，B 只补充结构与图注
  ⑤ 抽取目录 → 单元/课边界 → 对齐到页
  ⑥ 学科结构化抽取（见 6.3）
  ⑦ 写 data/parsed/<book_id>.jsonl（页行 + 课行）+ 学科表
```

### 6.2 关键决策

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| **双通道，而非单引擎** | 文本层为权威正文 + VLM 补充语义 | 实测：文本层+映射的拼音与 VLM **100% 一致**；但 VLM 会**重排顺序**（识字表页把第 8 课排到第 6 课之前、把「语文园地一」提前），不能作唯一权威来源 |
| **VLM 的定位** | 构建期一次性提取；无文本层册的唯一来源 | 全量 8384 页单线程需 35+ 小时；有文本层的 7107 页再走 VLM 是浪费（且引入顺序风险） |
| **拼音修复** | 字体映射（`HanyuXi-JZ`）而非 OCR / VLM | 实测本地 OCR 拼音不可用（`dirénniwóta` 粘连丢调）；映射零成本且与 VLM 逐条一致 |
| **扫描册** | 走 VLM 通道（1277 页，并发 8 约 50–60 分钟） | 实测能正确输出表格结构、注音与符号；本地 OCR 不行 |
| OCR 粒度 | 整册统一判定，不逐页混合 | 避免同册文本质量不一致导致切块错乱 |
| 目录获取 | 平台章节树 > PDF 目录页 > 正文规则 | 平台章节树最准；未接入时退回解析 |
| 公式处理 | V0 保留原文文本 + 记录所在页；不强行 LaTeX 化 | 公式识别错误率高，错误公式比不识别更糟 |
| **VLM 输出可回溯** | 保存 VLM 原始输出与模型版本 | 换模型/改提示词后可 diff，也能人工核对 |

### 6.3 学科差异化解析（★）

| 学科 | parse 阶段的额外要求 |
| --- | --- |
| **语文** | 抽取「识字表 / 写字表 / 词语表」（教材附录，格式规整，规则抽取即可）；课文按段落完整保留，**不做内容清洗**（文学性表达不能丢）；标注课文体裁与阅读策略单元；**抽取课文作者与出处**（"本文作者汪曾祺（1920—1997）"、"本文选自《呼兰河传》，作者萧红"）——即**作家锚点**，用于挂载该作家的作品集（见 6.8.5） |
| **数学** | **符号与公式保真**（+、×、÷、=、分数排版、单位）；区分例题 / 做一做 / 练习 / 复习题；公式页 OCR 错误率高，数学册优先文本层，OCR 册须人工抽检公式页 |
| **英语** | 词汇表抽取；对话按角色分行 |
| **科学** | 实验步骤与**安全提示**要能定位（后续 Guard 用于安全校验） |

### 6.4 双通道提取（★）

| 维度 | 通道 A 文本层 | 通道 B VLM |
| --- | --- | --- |
| 实现 | PyMuPDF + 拼音字体映射 | 渲染页图 → 多模态模型转录 |
| 拼音 | **100%**（与 VLM 逐条一致） | 正确，但偶发漏行 |
| 汉字 / 符号 | 完美，`÷ × （ ）` 保真 | 正确 |
| **原文顺序** | **严格保持** | **会重排**（多栏、跨块时按视觉重组） |
| 版式语义 | 无（只有字符串） | **强**：表格、知识结构图、图注、标题层级 |
| 速度 | 毫秒/页 | 14–30 s/页 |
| 成本 | 0，离线 | API 调用 |
| 适用 | 78 册 7107 页（主力） | 16 册 1277 页 + 结构补充 |

**选择规则**：

```
if 该页有文本层:  source = "text_layer"（正文权威），VLM 结果只作 structure 附注
else:             source = "vlm"（唯一来源）
```

**顺序风险与校验**（实测证据）：VLM 转录识字表页时，把第 8 课排到了第 6 课之前、把「语文园地一」提到了汉字行前。因此：

- **凡是顺序敏感的内容**（识字表按课归类、课文段落、题号），一律以通道 A 为准；
- VLM 仅用于顺序不敏感的语义补充（表格内容、图注、结构层级）；
- 两者冲突时记录 `conflict`，供人工抽检。

**并发与耗时**：该 VLM 接口并发能力很弱，实测 12 并发会因排队降到 30 秒/页、8 并发约 10 秒/页、
4 并发补零散页几乎不出活、1 并发补漏最稳。因此**批量求快用 8、补漏求稳用 1**（详见
`docs/02教材提取方案.md` §10）。文本层通道 4 并发，7107 页数分钟。

**插图理解纳入语料（★）**：教材里的图**不是装饰**——数学的几何图形、线段图、统计图，科学的实验装置与观察对象，少了图就读不懂题。所以扫描册走 VLM 时，提示词要求在图出现的位置插入：

```
[图N] 描述：图中画了什么、有哪些标注与数据、说明了什么规律或关系
```

图描述与文字转录在**同一次调用**内完成，不额外增加 API 成本。实测科学六下第 30 页输出 4 处描述（苔藓树干、松果球果、水稻、蕨类羽状复叶）；第 16 页把两张塔台设计图纸的标注（"上面：1个""侧面：2个"、三角形结构、底座塔身）还原成了文字。

> 注意：该模型是**推理型**模型，`max_tokens` 给小了会被推理 token 耗尽导致正文为空——默认已提到 8192，且 `content` 缺失时回退 `reasoning_content`。

文本层册的插图暂不单独处理（7107 页全量跑图理解不划算），后续按学科优先级补：**数学 > 科学 > 语文**（数学最依赖图）。

### 6.5 运行时多种方式（★）

构建期产出静态语料后，运行时 Agent 仍可按需要选择不同的内容获取方式——**VLM 适配器在构建期与运行期共用**：

| 方式 | 何时用 | 成本 |
| --- | --- | --- |
| 读 parsed 缓存（文本层） | 默认，绝大多数场景 | 0 |
| 读 parsed 缓存（VLM 结果） | 扫描册页面 | 0（构建期已付过） |
| **按需 VLM 解析指定页 / 图** | 教材里解释不清的插图、表格、实验装置图 | 每次一次 API |
| **按需 VLM 解析用户上传照片** | 孩子拍的作业题、试卷、手写作文 | 每次一次 API |
| 按需本地 OCR | 无网环境兜底 | 0 |

关键点：孩子拍一道作业题的照片 → 走**同一个 VLM 通道**转成文本 → 再进入 Agent 管线（判题、讲题、归因）。构建期与运行期复用一套 `VLMClient`，只是输入从"渲染的教材页"变成"用户上传的图片"。

> 因此 VLM 不是"构建期用完就扔"的工具，而是**贯穿构建期与运行期的基础能力**；构建期用它把教材变成语料，运行期用它把孩子的输入变成可处理的文本。

### 6.6 两阶段提取：构建期批量 + 运行期在线（★）

同一个 `VLMClient`，两个阶段共用，写的是**同一份产物**：

| 阶段 | 触发 | 输入 | 写哪里 |
| --- | --- | --- | --- |
| 构建期 | `parse` / `backfill` 命令 | 渲染的教材页 | `parsed/<book_id>.jsonl` + `vlm_raw/` |
| 运行期 | 孩子拍照提问、或问到没解析的页 | 上传图片 / 按需渲染的页 | 同上，**回填** |

```python
# 运行期在线提取（parse/online.py）
def transcribe_photo(image: bytes, prompt=None) -> str    # 孩子拍的题目照片 → 文本（含图描述）
def ensure_page(book_id: str, page_no: int, force=False) -> str   # 本地没有就当场解析并回填
def ensure_pages(book_id: str, page_nos: list[int]) -> dict       # 批量：并发解析，但只写一次盘
```

- 在线补出的页标记 `source=vlm_online`，与构建期的 `vlm` / `text_layer` 区分，meta 里累计 `online_pages`；
- 回填后进产物，下次直接命中（实测二次取同一页耗时 0.00s）。

**按需补的意义**：不是每册都值得预先批量跑。美术册整册约 1.5 小时而答疑价值很低；改成"问到哪一页补哪一页"，单次约 20 秒，补过就永久复用。**低价值册因此可以完全不进构建期计划。**

**断点续跑**：`vlm_raw/<book_id>/` 既是回溯证据，也是**缓存**。整册跑到一半中断，重跑时已解析的页直接复用，只补缺失页——实测中断在 63/94 页的册，重跑只补剩余部分，不浪费已完成页。

**单页失败不拖垮整册**：单页报错只把该页留空（`vlm_error` + 原因），已完成的页照常落盘；整册 meta 记 `failed_pages`，由 `backfill` 后续按页补。

### 6.7 全量核对与补齐

```bash
python -m agent_textbook backfill --dry-run   # 只核对
python -m agent_textbook backfill             # 核对 + 补齐（幂等，可反复跑）
```

三类缺口：

| 缺口 | 判定 | 补法 |
| --- | --- | --- |
| 空壳册 | 缺页 > 50%（扫描册） | 整册 VLM，断点续跑 |
| 空洞页 | 有文本层册里的个别空页（整页插图、封面） | 单页 VLM，含图描述 |
| 失败页 | `source=vlm_error` | 单页重跑 |

首轮核对实测：94 册 / 8384 页，待补 1155 页（空壳册 14 册 1102 页 + 零散 53 页）。

#### 6.7.1 ★ 只补插图：不动正文的第三条通道

**为什么不能复用正文通道**：`VLM_PROMPT_PAGE` 把「正文转录」与「插图描述」放在**同一次调用**
里完成——无文本层的扫描册必须如此，否则一个字都拿不到。但对**已有正文的文本层册**
（78 册 / 7107 页）就不能这么跑：用 VLM 重跑整页，会用转录结果**覆盖** PDF 内嵌文本
抽出来的正文，而后者更精确（拼音声调映射、数学符号无损）。

因此插图单独走一条通道：**只让模型描述插图，正文一字不动**，产物是侧车文件：

```
data/figures/<book_id>/<page_no>.md      # 每页图描述（[图N] 行，或一行 [无图]）
data/figures/_index.jsonl                # 追加式索引：book_id / page_no / figures / model / ts
```

```bash
python -m agent_textbook figures --subject 数学 --dry-run      # 核对
python -m agent_textbook figures --subject 数学 --workers 8    # 补齐（幂等，失败页下次补）
python -m agent_textbook figures --subject 数学 --limit 12     # 试跑 12 页看质量
```

产物不侵入 `parsed/`，可随时删除重来；检索时按 `(book_id, page_no)` 关联。

**实测质量**（数学三年级"观察物体"页）：

```
[图1] 左侧方框内展示了四只熊猫玩偶的不同视角图：左上是正面（头戴粉色蝴蝶结），
      右上是右侧面，左下是左侧面，右下是背面。
[图5] 右侧方框内展示了三幅长方体的视图：左侧是一个扁的长方形，中间是一个较长的
      长方形，右侧是一个竖着的长方形。
```

→ **三视图这类信息只有图里才有**，正文抽不出来。它是展现层（动画、虚拟实验、图文对齐）
的素材来源（知识库方案 §6.3），也是存储层要"可渲染"字段的原料。

**成本实测**：约 22 秒/页（4 并发，含重试）。按学科优先级推进：**数学 1412 页 → 科学 296 页**；
音乐、英语等图价值低的学科暂不补（全量 7107 页约 30–110 小时，不划算）。

### 6.8 扩展语料：教辅与课外书（★）

教材只是**根**，不是全部。教学形态还需要两类语料：**教辅**（怎么讲、怎么练）与**课外书**（读什么、用什么情境）。
但扩展语料不能"堆料"——由 **Agent 决策加工**决定何时取、取哪层、怎么用。

#### 6.8.1 三层语料

| 层 | 内容 | 锚点强度 | 在答案中的角色 | Guard 处理 |
| --- | --- | --- | --- | --- |
| **core 教材** | 课文、例题、字词表、习作要求、课后题 | **强**（册·单元·课·页） | **唯一事实源**：只有它能说"书上第 X 页写着…" | strict 的唯一依据 |
| **aid 教辅** | 讲解方法、知识梳理、梯度题、易错点、单元测评 | **强**（教辅按课/知识点编排，天然对齐教材） | **方法层**：怎么讲清楚、怎么练到位；**不充当"书上说"** | 可作讲解与出题依据，引用标 `[教辅·书名]`，**不得冒充教材** |
| **ext 课外** | 整本书（快乐读书吧推荐）、主题阅读、科普、传统文化 | **弱**（只能挂主题/要素锚点；推荐书目例外，锚点强） | **素材层**：拓展阅读与情境；**不参与事实判定** | 只在导入/拓展环节出现，**不进 strict 依据** |

关键区别：**core 决定"是什么"，aid 决定"怎么教"，ext 决定"用什么情境"**。三者混用会出事——孩子问"教材里怎么说"，拿教辅当教材答就是误导。

#### 6.8.2 Agent 决策加工（核心）

不是"全都检索进来让模型自己挑"，而是 **Planner 按「能力 × 教学环节 × 学情」显式决定取哪层**（对应语文教材本体 docx §7.1/7.2 的环节召回与学情适配）：

| 场景 / 能力 | core | aid | ext | 说明 |
| --- | --- | --- | --- | --- |
| 概念答疑、字词、阅读理解 | ✅ | ❌ | ❌ | 事实类只认教材，教辅不得介入 |
| 讲解方法（"怎么给孩子讲明白"） | ✅ | ✅ | ❌ | 教材给结论，教辅给讲法与类比 |
| 出题 / 练习（drill） | ✅ | ✅ | ❌ | 教材例题定标准，教辅补梯度与变式 |
| 错因归因与复习 | ✅ | ✅ | ❌ | 教辅的易错点库直接用 |
| 习作指导 | ✅ | ✅ | ⭕ | 教辅给支架；课外片段仅作**仿写素材**（须标来源） |
| 导入 / 拓展 / 整本书阅读 | ✅ | ⭕ | ✅ | 课外书在此登场，且必须挂要素或推荐书目锚点 |
| **思维拓展 / 奥数（数学）** | ✅ | ⭕ | ✅ | 只挂教材已有主题（「数学广角」/ 思考题）；须掌握度达标或主动要求；标"课内不要求"（见 9.4） |

**冲突仲裁**：`core > aid > ext`。教辅之间说法不一时，取与教材一致者；不一致则标注差异而非任选其一。
**超纲拦截**：教辅常超前（三年级教辅讲四年级内容），`scope_guard` 必须覆盖 aid 层，超出当前册要素范围的标为"课外选学"。

#### 6.8.3 工程影响

| 环节 | 改动 |
| --- | --- |
| 数据模型 | Chunk / Page 增 `source_tier`(core/aid/ext) + `anchor`（挂教材节点；ext 可为 `theme:<主题>`） |
| 采集解析 | 复用现有双通道（文本层 / VLM）；产物按 `tier` 隔离目录，`book_id` 命名空间带 tier，避免与教材混 |
| 检索 | 默认 core 优先；aid/ext 需按能力**显式放行**；ext 默认不进 strict 依据集 |
| 引用格式 | citation 强制带 tier 标签，UI 上分区展示（教材原文 / 教辅方法 / 课外素材） |
| Guard | strict 依据集 = core；aid 只能进"讲法/练习"，ext 只能进"素材" |
| 合规 | 教辅与课外书版权约束更严：仅本地个人使用，**不随产物分发、不入库共享** |

#### 6.8.4 风险

| 风险 | 对策 |
| --- | --- |
| 教辅说法与教材不一致 | 教材优先；记录 `conflict` 供人工抽检 |
| **教辅超纲** | `scope_guard` 覆盖 aid 层（教辅普遍超前于教材进度） |
| 孩子误以为"教材里写的"实为教辅 | citation 强制带 tier，UI 明确区分 |
| 课外书无锚点导致跑题 | **无锚点不入库**；只能挂主题/要素锚点，或来自教材"快乐读书吧"推荐书目 |
| 教辅质量参差 | 入库前标注来源与版次；低质来源降权；关键结论仍回教材校验 |

> 落地顺序建议：**先教辅、后课外**。教辅锚点强（按课编排）、风险低、直接补上"怎么讲怎么练"的缺口；
> 课外书锚点弱、易跑题，等教学环节与要素锚点建好后再接（对应语文教材本体 docx §6.5 的"整本书阅读库"插件）。

#### 6.8.5 知识来源阶梯：内化 → 上传书籍 → 教材原文（★）

模型自身的**内化知识**也是一种来源，但它不可溯源、偏笼统，还可能张冠李戴（把不同作家的风格记混）。
所以把它纳入体系，但**限定用途**：

| 级别 | 来源 | 可溯源 | 合法用途 | 标注要求 |
| --- | --- | --- | --- | --- |
| **内化知识** parametric | 模型自身 | ❌ | **仅创作类与方法性建议**：习作指导、讲法类比、学习建议。**事实类禁用** | 必须标注"这是一般写作经验，不是教材内容" |
| **上传书籍** ext（挂锚点） | 用户提供的作家作品集 / 课外书 | ✅（书名·篇名·页码） | 示范片段、仿写素材、风格分析、拓展阅读 | 引用带书名与篇名 |
| **教材原文** core | 教材 | ✅（册次·页码） | 事实依据、习作要求与 rubric | 引用带册次·页码 |

**核心机制**：上传书籍把"内化知识"**升级为可溯源语料**——同一件事，从"模型说汪曾祺语言清淡"变成
"引《自报家门》里他写看车匠、看灯笼铺那段，看清淡是怎么来的"。

**实证：以汪曾祺为例**（教材语料里已有 3 处锚点）

| 教材锚点 | 内容 |
| --- | --- |
| 三下 P12 | 《昆虫备忘录》，注释"本文作者汪曾祺（1920—1997）" |
| 三下 P22 | 选自《自报家门》："到车匠店看车匠用硬木车旋出各种形状的器物…百看不厌" |
| 五年级 P112 | 选自《谈读杂书》："唐宋八家，不如多看杂书…这是我的经验之谈" |

| 场景 | 只有内化知识 | 上传《汪曾祺集》后 |
| --- | --- | --- |
| 讲"怎么写昆虫" | 泛泛说"写细致、多用短句" | 引他写蜻蜓瓢虫的原句：怎么用短句、怎么插入联想（"我曾经想过：如果人长了一对复眼…"） |
| 讲语言风格 | 可能与梁实秋、丰子恺的风格混淆 | 引《自报家门》他自述看车匠、看灯笼铺——"清淡"有据可依 |
| 仿写支架 | 只给提纲 | 给"观察 + 联想 + 口语化短句"的可模仿片段 |

**教材本身就在做这件事**：六下 P11 要求"读下面的句子，体会老舍'京味儿'语言的特点"——
**教材给任务，作家作品集给素材**。这类题目以前只能靠模型内化知识硬答，有了作家的书就能引原文对照。

> 同类作家锚点在教材里很密（实测：叶圣陶 13 处、老舍 9 处、冰心 9 处、丰子恺 7 处、巴金 6 处、
> 萧红 4 处、冯骥才 3 处），且均带"本文作者 X（生卒年）"或"本文选自《Y》"的规整注释——
> **规则抽取即可，无需 LLM 猜**。

## 7. 阶段三：index 设计

### 7.1 切块（分学科）

| 内容 | 策略 |
| --- | --- |
| 一般正文 | 按课切 → 课内按页 → 页内超长按 300–500 字滑窗（overlap 50–80 字）；**不跨课** |
| **语文课文** | **整篇不切块**，独立存 `LessonText`，检索时整篇注入（课文几百字，切块会破坏语境） |
| **语文字词** | 不进向量库，进 SQLite 字词表，走精确匹配 |
| **数学题** | 题目 + 解法步骤整体成块，标注 `type`，便于"找同类例题" |
| **习作** | 习作要求与 rubric 单独索引，供写作任务检索 |

### 7.2 索引

| 索引 | 用途 | 实现 |
| --- | --- | --- |
| 元数据表 | 硬过滤（学段/学科/版本/年级/册次/课） | SQLite `chunks` 表 |
| 向量索引 | 语义召回 | `sqlite-vec` 或 FAISS（3–5 万块，CPU 够用） |
| BM25 | 术语精确匹配（"分数的初步认识"） | `bm25s` |
| 页级索引 | 取某页原文 | SQLite `pages` 表 |
| **课文表** | 整篇课文存取 | SQLite `lesson_texts` |
| **字词表** | 精确查字 | SQLite `words`（按 `char`/`pinyin` 建索引） |
| **题库表** | 按类型/知识点找题 | SQLite `problems` |

### 7.3 检索流程

```
问题 + 作用域（年级/学科/册次/课）+ 学科 Profile 指定的检索策略
   ├─ ① 路由检索方式：查表 / 语义检索 / 整篇课文
   ├─ ② 元数据硬过滤：先框定「三年级·数学·上册」
   ├─ ③ 语料层放行：按能力决定是否纳入 aid / ext（事实类只取 core，见 6.8.2）
   ├─ ④ 双路召回：向量 top-50 + BM25 top-50
   ├─ ⑤ RRF 融合 → top-20 → 重排 → top-5（core 优先，同分时教材胜出）
   └─ ⑥ 连页码 + tier 元数据一起交给 Agent
```

**过滤先于检索**：教材内容跨年级螺旋重复，不过滤必然串年级。

**分层先于融合**：core/aid/ext 不混在一个候选池里等模型自己挑——
由 Planner 在 ③ 显式决定放行哪几层，避免教辅或课外内容挤掉教材原文。

### 7.4 索引运维（借鉴 DeepTutor）

- **版本化**：重建写入 `data/index/v{N}/`，完成后切换指针；旧版保留，**重建中绝不破坏可用索引**。
- **单册增删**：换教材版本只重跑该册。
