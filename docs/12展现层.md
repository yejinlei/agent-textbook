## 6. 展现层：形态与呈现（★ 补充）

> 存储层解决"**说得对**"，展现层解决"**孩子能不能接收到**"。

### 6.1 为什么必须单列

同一个知识点：给三年级一段两百字说明，和给一个 3 秒动画，**效果是两个世界**。
存储再准，如果出口只有一坨 Markdown，产品不成立——
**对小学生而言，呈现错了就等于没送到。**

### 6.2 形态矩阵

| 形态 | 适用 | 代价 |
| --- | --- | --- |
| 文本 / 对话 | 默认答疑 | 低 |
| **动画** | 数学（分数、线段图）、科学过程 | 中，**必须模板化** |
| 音频 | 英语跟读、低年级听读 | 需 TTS（V1） |
| HTML 交互 | 虚拟实验、可操作图形 | 中 |
| PPT / 视频 | 复习、讲给家长 | 高（生成慢） |
| 游戏化 | 口算、字词 | **低（0 次 LLM）** |
| 引导式 guided | 探究流程、习作支架 | 中 |

**形态由学科 Profile 决定，不由模型自由选**：语文不给 game，数学优先 animation，
英语优先音频，科学优先 HTML 仿真（见 `07学科设计.md` §9）。

### 6.3 硬约束

1. **动画必须参数化模板**：数值取自教材例题，**不让模型自由画**——
   画错的分数动画（切错份数）比不画更糟，与"不编造"同源。
2. **教材插图描述是素材**：VLM 已把插图转为描述入库，可直接作为动画 / 仿真脚本的结构来源。
3. **适龄**：低年级少字多图、生僻字注音，不用中高年级句式。
4. **同一内容多形态复用同一份 `ContentPlan`**：先定结构再渲染各形态，
   不是每种形态各生成一次（否则三种形态三种说法）。

### 6.4 ★ 展现层对存储层的反向要求（回写到存储设计）

| 展现需求 | 存储层要有的字段 |
| --- | --- |
| 动画 | **结构化数值**（`stem / answer / steps`），不是段落文本 |
| PPT | 知识点**层级结构**（知识点 → 要点 → 例子）→ 切块不能切碎层级 |
| 音频 | **可朗读形式**（"三分之一" 而非 `1/3`）→ 公式另存朗读文本 |
| 游戏化 | **有唯一答案的离散题**（`answer` + 判等规则） |
| 虚拟实验 | 实验条目含**材料与参数** |
| 图文关联 | 插图描述与正文**按页对齐** |

→ **存储层不是"先存够文本再说"**：字段设计要同时满足决策层（可溯源、可路由）
与展现层（可渲染）。这与 §4.4「关系要少、属性要多」是同一条逻辑——
**属性就是给决策与呈现用的**，事后补代价极高。

### 6.5 三层与一条侧链

```
[教材侧] 教材 → 解析 → 存储层（精确表 / 文本块 / 要素表 / 词条缓存）
                            ↓ 带引用
[决策层] Router → Retriever → Teacher → Guard
                            ↓ 过检的 ContentPlan
[展现层] Presenter → 文本 / 动画 / 音频 / HTML / PPT / 游戏
   ↑                                        ↓
[用户侧] 画像 + 全量交互（`06记忆与用户数据.md` §8.12） ←── 反馈回流
```

### 6.6 界面：容器与交互（★ 补充）

> 前几节解决"内容长什么样"（形态矩阵），本节解决"**壳长什么样**"（布局、导航、输入、多视图）。

#### 6.6.1 现状与选型

| 事实 | 值 |
| --- | --- |
| 现有界面 | **无**（仅 CLI，且只有教材处理命令：catalog / parse / backfill / photo） |
| 用户 | **孩子（主）+ 家长（次）** |
| 约束 | 本地运行、数据不出本机 |

| 方案 | 判断 |
| --- | --- |
| **本地 Web**（FastAPI + 轻前端） | ★ **选它**：同栈 Python、免安装、平板 / 手机同局域网可访问 |
| Tauri / Electron 桌面 | ✗ 引入 Rust / Node 工具链，与"依赖精简"（§5.6.1）冲突 |
| 纯 CLI | ✗ 孩子无法使用 |

→ **前端是薄壳**：所有逻辑在后端 Agent，前端只负责呈现与输入（对应 §5.2 的 Presenter）。

**★ 界面范式：Agent Native，不是"管理网站内嵌 Agent"**

| | 传统 Web 内嵌 Agent | **Agent Native（选它）** |
| --- | --- | --- |
| 主入口 | 菜单导航，Agent 只是其中一个页面 | **一个总入口**，所有任务从这里进 |
| 六种入口 | 变成六个菜单项（**路径固化**） | 对话里的任务（灵活） |
| 与后端架构 | **冲突** | **一致** |
| 结构化信息 | 页面展示（强） | **对话内富卡片**（够用） |
| 膨胀风险 | 菜单越来越长 | 低 |

**关键论证——界面形态必须与执行架构一致**：
§5.6.4 已定"**Agent 为主，不是固定 workflow**"。而**菜单本质上是 workflow 的界面化**
（先点哪个、再点哪个，路径写死）。若前端用固定菜单，等于把六种入口固化成六条路径，
**Agent 的灵活性在前端被掐掉**。选了 Agent 后端，就要 Agent Native 前端——否则界面成为瓶颈。

**但 Agent Native ≠ 空白聊天框**（§6.6.2 的问题依然存在）：

- 六个按钮是**快捷启动器**，**不是菜单**——点了是在对话流里**启动一个任务**，不跳转页面；
- 结构化信息（掌握度、进度、错题）以**富卡片**呈现在对话流中，不是纯文字；
- 进度坐标常驻顶栏（§6.6.2）。

**保留少量传统页面（约 10%）**：设置、数据导出 / 删除、错题本深度浏览——
这类"管理与批量操作"在对话流里确实难用，用传统页面兜底。**它们是后台，不是主界面。**

**家长不建独立站点**：同一入口 + 家长模式切换（可见学情卡片与设置），
避免维护两套界面。

#### 6.6.2 ★ 主界面：不是空白聊天框

孩子面对空白输入框**不知道能问什么**，容易跑偏。界面要给结构：

```
┌────────────────────────────────────────────┐
│ 三年级·语文·上册 · 第3单元 第9课     [切换]  │ ← ★ 进度坐标（常驻）
├────────────────────────────────────────────┤
│ [提问] [交作业] [预习] [复习] [听写] [习作]   │ ← 入口（§5.6.4 六种入口）
├────────────────────────────────────────────┤
│                                            │
│   内容区（富容器：文本 / 动画 / 音频 / 交互）  │
│                                            │
│   ┌ 来自：三上语文 P42 ──────────┐  ← ★ 引用可见
│   │ …                             │     （可点开看原文）
│   └───────────────────────────────┘
├────────────────────────────────────────────┤
│ 输入框              [📷 拍照] [🎤] [发送]     │
└────────────────────────────────────────────┘
```

两个非常规设计，也正是差异化所在：

1. **进度坐标常驻顶栏**——整个系统的锚点就是"现在在第几课"，它必须一直可见、可切换
   （对应系统设计 §8.11 进度）。**竞品的 AI 对话没有"你在教材哪一页"这个概念。**
2. **★ 引用可见**——答案旁标注"来自 三上语文 P42"，可点开看原文。
   把后端的"可溯源"（§4）变成**用户看得见的信任**；这是竞品没有的。

#### 6.6.3 侧栏：目录树

教材目录（单元 → 课），点击即跳转——它是 §4「目录即图谱」的界面化，
不是装饰，而是**导航与进度坐标系**。

#### 6.6.4 家长视图

| 项 | 内容 |
| --- | --- |
| 学情 | 各科掌握度、薄弱点、错因分布 |
| 错题本 | 可导出、可打印 |
| **进度** | **教学进度 vs 掌握进度**（§8.11.2 双进度）→ **"学到第 8 课但只掌握到第 5 课"要一眼看出** |
| 设置 | 时长上限、学科、教材版本 |
| 数据 | 导出 / 一键删除（§8.12.5） |

★ **双进度必须可视化**：这是家长最需要的一眼信息，也是本产品区别于"AI 聊天"的关键。

#### 6.6.5 ★ 儿童界面的硬约束（产品伦理，与"不编造"同源）

| 不做 | 理由 |
| --- | --- |
| **连续打卡 / 签到奖励** | 用损失厌恶绑定孩子 |
| **排行榜、积分商城** | 外在动机挤掉内在动机 |
| **无限滚动 / 自动播放** | 延长停留时间的设计对儿童有害 |
| **抽奖式随机奖励** | 变比率强化最易成瘾 |

→ **目标不是"让孩子用得久"，而是"让孩子学会后离开"。**
**使用时长不作为产品指标**——这与"AI 补上班级授课制缺口"的定位一致：
补上缺口就该结束，不该制造依赖。

其余要求：**大字少字多图**（低年级尤甚）、**即时反馈**（流式输出 + "正在看课本…"提示，
孩子等不了 30 秒）、**可随时中断**。

#### 6.6.6 界面与展现层的分工

| | 职责 |
| --- | --- |
| **界面**（本节） | **容器**：布局、导航、输入、多视图切换 |
| **展现层**（§6.2 形态矩阵） | **内容**：文本 / 动画 / 音频 / HTML / 游戏 |

内容区是**富容器**，按 `ContentPlan.form` 渲染对应形态——
两者解耦，新增形态不需要改界面骨架。

### 6.7 ★ 多模态：输入与输出的完整矩阵

前面几节偏重"输出形态"，但**输入同样是多模态的**（文字 / 语音 / 图片），
且两种模态之间每次转换都会引入错误。本节补齐完整矩阵。

#### 6.7.1 输入模态

| 模态 | 现状 | 适用 | 阶段 |
| --- | --- | --- | --- |
| 文字 | ✅ | 全年级 | V0 |
| **图片 / 拍照** | ✅ `photo` 命令（VLM 转录） | **作业、卷子、课本页** | V0 |
| 语音 | ❌ 需 ASR | **低年级（不会打字）**、英语跟读 | V1 |
| 手写 / 涂鸦 | ❌ | 手写作答 | V1 |

**★ 语音的价值随年级递减**（实证）：教材里"说一说 / 读一读 / 朗读 / 讲一讲"类口头指令的占比——

| 年级 | 一 | 二 | 三 | 四 | 五 | 六 |
| --- | --- | --- | --- | --- | --- | --- |
| 占比 | 11.2% | **15.6%** | 10.3% | **9.0%** | 12.7% | 9.8% |

→ **低年级约 13–16%，高年级降到 9%**。叠加"一二年级孩子打字很慢"这一事实：
**语音输入对低年级是刚需，对高年级只是便利。**

#### 6.7.2 输出模态（按性价比排序）

| 模态 | 成本 | 教育价值 | 阶段 |
| --- | --- | --- | --- |
| 文字 | 低 | 基础 | V0 |
| **交互 HTML**（可拖、可改参数） | 中 | **★ 最高** | V0/V1 |
| 动画 | 中 | 高（数学 / 科学） | V1 |
| **音频 / 播客** | **低**（TTS） | 中高（耳朵空闲：通勤、睡前；英语跟读） | V1 |
| PPT | 中 | 中（复习、讲给家长） | V1 |
| **视频** | **最高** | **中**（单向被动） | V2 |

**★ 反直觉：视频最贵，但对小学生未必最有效。**
视频是单向被动的——**做视频是跟短视频抢地盘（红海），做交互才是 AI 真正的优势（蓝海）**。
孩子"看视频"和在短视频平台看科普没有区别；但"拖一拖、改个参数看结果"是视频做不到的。

→ **优先级：交互 > 动画 > 音频 > PPT > 视频。**

**播客值得单说**：它只是"文字 → TTS"，成本远低于视频，
却利用了视频用不上的场景（孩子耳朵空闲时）。**性价比高于视频。**

#### 6.7.3 ★ 模态转换的校验点（每转一次就多一次出错机会）

| 转换 | 风险 | 校验 |
| --- | --- | --- |
| 图片 → 文本（VLM） | **看错题、漏条件** | **回显确认**（"这是第 3 题吗？"） |
| 语音 → 文本（ASR） | 听错、儿童口音 | **回显确认**（"我听到的是…"） |
| 文本 → 语音（TTS） | **多音字、公式读错**（`1/3` 读成"一斜杠三"） | 存**朗读文本**（§6.4），不拿原文直接读 |
| 文本 → 动画 | 画错（切错份数） | **参数化模板**，数值取自教材（§6.3） |
| **文本 → PPT / 播客 / 视频** | **★ 丢失引用** | **产物必须带教材引用** |

**★ 最后一条最易漏**：PPT、播客、视频里**最容易丢掉"来自课本哪一页"**。
一旦丢了，产品就退化成普通的 AI 生成内容，**可溯源体系在最后一环断掉**。

→ **硬约束：任何形态的产物都必须带教材引用**，
音频里也要说"这段来自课本第 42 页"，PPT 每页角落标注出处。

#### 6.7.4 存储与依赖

| 模态 | 存储 |
| --- | --- |
| 文字 | 全留（§8.12.7） |
| 图片 | 压缩后留 |
| **音频（TTS 产物）** | **不存文件**，只存文本与参数——**可重放再生成** |
| **视频** | **不存**，同上 |

依赖：TTS（Piper / ChatTTS）、ASR（Whisper）→ V1 引入，进 `optional-dependencies`，
不进核心依赖（与 §5.6.1「依赖精简」一致）。
