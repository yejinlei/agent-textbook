## 14. 实施计划

### 14.0 构建策略：垂直切片优先（★）

知识库形态的选型已定（见 `10知识库选型.md` §4）：**RAG 原文层为永久底座 + 目录树作图谱骨架 +
轻量本体 + wiki 仅作热点缓存，不做重型知识图谱**。因此这里要决策的不是选型，而是**构建顺序**。

| 路线 | 做法 | 判断 |
| --- | --- | --- |
| **自上而下**（先做 PPT / 播客 / 视频） | 先搭功能壳，后面接知识库 | ❌ **不建议** |
| 水平分层（数据 → 检索 → Agent → 学科 → 形态） | 每层做完再进下一层 | ⚠️ 底座可以，**全链路不行** |
| **垂直切片** | 一条能力从数据打通到形态与评测 | ✅ **采用** |

**为什么不从形态层起步**

PPT / 播客 / 视频在**没有知识库时也能做**——让 LLM 直接生成一份课件只要一天。问题恰恰在这里：
它与豆包没有区别，我们花大力气做的教材锚定被绕过去了。更要命的是**漂亮的输出会掩盖错误**——
一张排版精美的 PPT 里引用错了页码，家长根本看不出来。
反过来则完全不同：先有 strict 引用校验，再套 PPT 模板，**质量是继承的，模板只是几天的活**。

> **形态层是"格式转换器"，不是"功能"。这个项目的价值在锚定，不在排版。**

**为什么不全链路水平分层**

形态会**反向约束数据**：数学动画需要参数化的数值（不是自由文本），PPT 需要大纲结构（不是 chunk 列表）。
等到 M7 才考虑形态，前面的数据模型已经定型，只能返工。
（VLM 那次就是这个教训：跑了几小时才发现方向偏了。）

因此：**M0–M2 作为共性底座不变**（数据已就绪，检索与单 Agent 是共用层且规模小）；
**从 M3 起，每条学科线都是一条垂直切片——数据、检索、Guard、形态、评测一起做完、一起验收。**

**★ 形态层要按受众拆，它们根本不是同一件事**

| 形态 | 受众 | 定位 |
| --- | --- | --- |
| **动画 / 交互仿真** | 孩子 | **认知必需品，不是美化**：数学的过程性知识（怎么分、怎么变）用文字讲 200 字仍懵，动画 3 秒就懂 → **跟着切片早做** |
| **游戏**（口算 / 枚举） | 孩子 | 0 次 LLM、成本为零、错因驱动 → 早做 |
| **PPT 课件** | **老师 / 家长** | 孩子不读幻灯片 → 中优先级，管线稳定后套模板 |
| **播客** | **家长** | 小学生不听播客；价值在"给家长的学情解读" → Parent 角色的输出形态，低优先级 |
| **视频** | 孩子 / 家长 | 不做"AI 生成视频"（红海且不可控）；我们的视频 = **教材动画 + 配音**，与动画同源 |

> **孩子侧（动画 / 游戏 / 对话）先做，家长侧（PPT / 播客 / 报告）后做。**

| 里程碑 | 内容 | 交付物 |
| --- | --- | --- |
| **M0a 文本层通道** | `parse/extract`：**PyMuPDF + 拼音字体映射** + 目录解析 + **学科表抽取**（语文字词表、数学题型标注） | 78 册解析完成，拼音 100% |
| **M0b VLM 通道** | `VLMClient`（**构建期与运行期共用**）+ 扫描册提取 + 与文本层**交叉校验**与冲突标记 | 16 册解析完成，冲突可查 |
| **M1 检索** | `index`：切块 + 向量 + BM25 + **课文整篇表 / 字词表 / 题库表** + 元数据过滤 | `search` 可用 |
| **M2 单 Agent** | `agents/runtime`：一个 loop + 工具；Teacher 单角色 + strict 引用约束 | `ask` 可用（先只做事实类） |
| **M3 数学线（★ 垂直切片 1）** | `subjects/math.py`：题目与**思维标签**抽取 → 解题分步 + derivation Guard + 验算 + 错因到思维断点 + 口算生成 **+ 动画模板（分数/线段图） + 端到端评测** | `solve` / `drill` 可用，**且指标达标**（答案 ≥90%、引用 ≥90%、步骤 ≥85%） |
| **M4 语文线（★ 垂直切片 2）** | `subjects/chinese.py`：字词查表 + 阅读理解整篇注入 + 习作 rubric（不代写） **+ 沉浸式课文 `read`（分段讲 + 沿途提问） + TTS 朗读/听写** | 字词/阅读/写作指导可用，**定位准确率 ≥85%、拒答 ≥95%** |
| **M5 多 Agent 完整** | Router / Planner / Quizzer / Grader / Coach / **Assistant** / Parent / Learner 上线 | 全能力 |
| **M6 评测** | 检索评测 + 分学科端到端 + Guard 漏检/误杀 + 回归门 | 指标达标 |
| **M5′ 英语线（★ 垂直切片 3）** | `subjects/english.py`：词汇与句型表抽取 → **范围锁定校验 `check_vocab_scope`** → 角色扮演 + 跟读评分 | 超纲词率 **0**、查表 ≥99%（需语音栈，可延后） |
| **M5″ 科学线（★ 垂直切片 4）** | `subjects/science.py`：实验清单（含材料与安全）→ 探究引导 + 参数化仿真 + `check_safety` | **安全提示召回率 100%** |
| **M7 家长/老师侧形态** ★ | **PPT 课件**（套已验证内容）、播客式学情解读、家长报告；Web 界面完善 | 从"能答"到"能给家长用" |
| **M8 教学闭环** | 掌握度路径 `mastery`（按要素设闸门，达标放行）、图形可视化 `visualize`、教材内探究 `research`、记忆三层、家长视角 | 完整教学闭环 |

**顺序理由**：M0–M2 先打通「事实类」单 Agent 闭环（这是 strict 模式，最严格、也最容易验证）；M3/M4 再分别攻克数学（推导类）与语文（查表 + 创作类）——这两条线的校验机制本质不同，分开做才能各自调优，混在一起会导致 Guard 规则互相妥协。

**先数学后语文**：数学的 derivation 有客观验算标准（答案对不对可自动判），容易测；语文的 rubric 需要人工校准，成本更高。先拿下可自动验证的部分。

**每片都要自带评测**：垂直切片的意义在于"这一片能不能真的用"——所以 M3–M5″ 每一片都绑定了量化验收
（M6 的统一评测是在此基础上做回归门，不是事后补测）。**没有指标的切片等于没做完。**

**形态跟着切片走，不集中到最后**：数学动画随 M3、课文朗读随 M4、语音对话随 M5′、科学仿真随 M5″；
只有**家长/老师侧**（PPT / 播客 / 报告）集中到 M7——它们本质是已验证内容的格式转换。
