# 系统设计文档

> `agent-textbook`：面向小学生的教材 Agent 工程。
> 本文是工程实现蓝图：**模块划分、数据模型、接口约定、存储布局、实施计划**。
> 知识库形态的选型论证见 `docs/知识库方案.md`；采集阶段的原理与用法见 `docs/教材提取原理与使用.md`。

---

## 1. 目标与非目标

### 目标

- 基于**本地教材原文**回答小学生与家长的问题，答案必须可溯源到册次、页码。
- 能按「孩子当前在读哪一册哪一课」精确定位，不串年级、不串版本。
- 支持讲解、举例、出题与批改。
- 单机 Windows 可跑完，无需 GPU，零运维。

### 非目标

- 不做通用百科问答（语料只限教材）。
- 不做多模态大模型（V0 只处理文本与图注，插图理解留到后续）。
- 不追求自动构建大规模知识图谱（见选型文档 4.3）。
- 不做多用户、不做服务端部署。

### 硬约束

| 约束 | 说明 |
| --- | --- |
| 可溯源 | 每个回答必须带 `册次 + 页码` 引用；检索不到依据时必须回答「教材里没有」 |
| 版本隔离 | 语文统编版 / 数学人教版等不同版本产物互不混用 |
| 离线可跑 | 解析、切块、嵌入、检索全部本地完成；LLM 生成可选 API 或本地模型 |

## 2. 总体架构

```
┌────────────┐   ┌────────────┐   ┌────────────┐   ┌────────────┐
│ ① collect  │──▶│ ② parse    │──▶│ ③ index    │──▶│ ④ agent    │
│  采集 PDF   │   │  文本/OCR  │   │  切块+索引  │   │  答疑/出题  │
│  ✅已实现    │   │  目录抽取   │   │  向量+BM25 │   │  引用原文   │
└────────────┘   └────────────┘   └────────────┘   └────────────┘
  books/*.pdf      parsed/*.jsonl    index/*         回答 + 引用
       │                │               │               │
       └────────────────┴───────────────┴───────────────┘
              data/downloads.jsonl 是贯穿全程的元数据契约（以 id 为键）
```

数据流与产物：

| 阶段 | 输入 | 产物 | 状态 |
| --- | --- | --- | --- |
| collect | 平台接口 | `books/<地区>/<学段>/<学科>/<版本>/<年级>/*.pdf`、`data/downloads.jsonl` | ✅ 已实现 |
| parse | `books/*.pdf` + 清单元数据 | `data/parsed/<book_id>.jsonl`（页/课/文本来源） | 待实现 |
| index | `data/parsed/*.jsonl` | `data/index/meta.sqlite3` + 向量库 + BM25 | 待实现 |
| agent | 索引 + 用户问题 | 回答（含引用）、题目、讲解 | 待实现 |

## 4. 数据模型

以 `book_id`（平台 contentId）为主键贯穿全程。

### 4.1 Book（来自 `downloads.jsonl`）

| 字段 | 说明 |
| --- | --- |
| `id` | 平台 contentId，全局主键 |
| `region` / `stage` / `subject` / `version` / `grade` | 分类元数据（浙江杭州 / 小学 / 数学 / 人教版 / 三年级） |
| `volume` | 册次（上册/下册），从 `title` 解析 |
| `title` | 书名 |
| `path` | 相对 `books/` 的文件路径 |
| `preview_url` | 平台在线预览页（人工核对用） |

### 4.2 Page（解析产物，一行一页）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `book_id` | str | 外键 |
| `page_no` | int | 物理页码（1-based，与书上页码可能不同，见下） |
| `printed_no` | str | 书上印的页码（若能识别） |
| `text` | str | 页面文本 |
| `text_source` | enum | `text_layer` / `ocr` / `empty` |
| `confidence` | float | OCR 置信度（`text_layer` 时为 1.0） |
| `images` | list | 图注文本、图上 OCR 文本（V0 只存文本） |

> 扫描版教材的物理页码与书上页码常不一致，需建立 `page_no ↔ printed_no` 映射表，否则引用页码会错。V0 先按物理页码引用并注明。

### 4.3 Section（课 / 单元）

| 字段 | 说明 |
| --- | --- |
| `book_id` / `section_id` | 主键 |
| `unit` | 单元号与单元名（如「第三单元 分数」） |
| `lesson` | 课号与课名（如「1. 分数的初步认识」） |
| `start_page` / `end_page` | 页范围 |
| `title` | 课标题 |

来源优先级：① 平台章节树（`trees/{ebook_id}.json`，需接入，见采集文档 FAQ）→ ② PDF 目录页解析 → ③ 正文规则识别（"第 X 单元"/"X." 行首模式）。

### 4.4 Chunk（检索单元）

| 字段 | 说明 |
| --- | --- |
| `chunk_id` | `book_id:page_no:seq` |
| `text` | 块文本（300–500 字） |
| `book_id` / `page_no` / `section_id` | 溯源定位 |
| `meta` | 学段/学科/版本/年级/册次/单元/课（**冗余存储，供硬过滤**） |
| `vector` | 嵌入向量（存于向量库，按 chunk_id 对齐） |

### 4.5 KnowledgePoint / WikiEntry（L1/L2 层，见选型文档）

```python
KnowledgePoint: id, name, subject, first_grade, first_volume,
                appears_in: [(book_id, page_no)], prerequisites: [kp_id]
WikiEntry:      kp_id, definition, examples[], pitfalls[],
                citations: [(book_id, page_no)], generated_at, source_hash
```

## 5. 阶段二：parse 设计

### 5.1 流程

```
对每本 status=ok 的教材：
  ① 打开 PDF → 逐页抽取文本层
  ② 判定：平均每页字符数 < 阈值（建议 50）→ 该册标记 need_ocr，整册走 OCR
  ③ 抽取目录 → 单元/课边界 → 对齐到页
  ④ 写 data/parsed/<book_id>.jsonl（页行 + 课行）
```

### 5.2 关键决策

| 决策 | 方案 | 理由 |
| --- | --- | --- |
| 文本 vs OCR | 先试文本层，不足才 OCR | 94 册中约 17 册为高清图版（科学、书法），其余文本层可用，OCR 成本高 |
| OCR 粒度 | 整册统一判定，不做逐页混合 | 避免同册内文本质量不一致导致切块错乱 |
| OCR 引擎 | RapidOCR / PaddleOCR（中文，CPU） | 中文教材，本地可跑 |
| 目录获取 | 平台章节树 > PDF 目录页 > 正文规则 | 平台章节树最准且有官方结构；暂无接入时退回解析 |
| 公式处理 | V0 保留原文文本 + 记录公式所在页；不强行 LaTeX 化 | 公式识别错误率高，错误公式比不识别更糟 |

### 5.3 接口

```python
# parse/extract.py
def extract_pages(pdf_path: str) -> list[Page]          # 文本层抽取
def ocr_pages(pdf_path: str, dpi: int = 200) -> list[Page]  # 扫描版 OCR

# parse/toc.py
def parse_toc(pdf_path: str, pages: list[Page]) -> list[Section]
def align_sections(sections, pages) -> list[Section]    # 补全 start/end_page

# parse/pipeline.py
def parse_book(rec: dict) -> str                        # 返回 parsed 文件路径
def parse_all(workers: int = 4) -> None                 # 遍历清单中 status=ok 的条目
```

### 5.4 命令行

```powershell
python -m agent_textbook parse                                   # 全量解析
python -m agent_textbook parse --subject 科学 --force-ocr         # 指定学科强制 OCR
python -m agent_textbook parse-status                            # 解析进度与 OCR 占比
```

## 6. 阶段三：index 设计

### 6.1 切块策略

1. **按课切**：一课是教材的天然语义单位，优先以 `Section` 为边界；
2. **再按页**：课内以页为单位保留页码；
3. **再滑窗**：单页超长时按 300–500 字滑窗，overlap 50–80 字；
4. **不跨课切块**：保证每个块的溯源唯一。

### 6.2 索引结构

| 索引 | 用途 | 实现 |
| --- | --- | --- |
| 元数据表 | 硬过滤（学段/学科/版本/年级/册次/课） | SQLite `chunks` 表，字段建索引 |
| 向量索引 | 语义召回 | `sqlite-vec` 或 `faiss`（3–5 万块，CPU 够用） |
| BM25 | 术语精确匹配（"分数的初步认识"） | `bm25s`，序列化到磁盘 |
| 倒排（可选） | 知识点 → 页码 | SQLite 表 |

### 6.3 检索流程

```
用户问题 + 作用域（年级/学科/册次）
   │
   ├─ ① 元数据硬过滤：先框定「三年级·数学·上册」
   ├─ ② 双路召回：向量 top-50 + BM25 top-50
   ├─ ③ RRF 融合 → top-20
   ├─ ④ 重排（bge-reranker，仅 top-20）→ top-5
   └─ ⑤ 连同页码元数据交给 agent 生成
```

**过滤先于检索**是本项目最重要的检索策略：教材内容在不同年级高度重复（螺旋上升），不过滤必然串年级。

### 6.4 接口

```python
# index/chunk.py
def chunk_book(parsed_path: str) -> list[Chunk]

# index/embed.py
def embed(texts: list[str]) -> np.ndarray

# index/store.py
def build_index(chunks: list[Chunk]) -> None
def upsert(book_id: str, chunks: list[Chunk]) -> None   # 增量/换版重跑

# index/retrieve.py
def search(query: str, scope: dict, top_k: int = 5) -> list[tuple[Chunk, float]]
```

### 6.5 命令行

```powershell
python -m agent_textbook index                          # 全量建索引
python -m agent_textbook index --subject 数学            # 只重建某学科
python -m agent_textbook search "什么是分数" --grade 三年级 --subject 数学
```

## 7. 阶段四：agent 设计

### 7.1 问答流程

```
问题 → 澄清作用域（年级/学科，缺失则追问或按默认）→ 检索 → 有依据？
   ├─ 有 → 生成（引用格式：三年级上册 数学 P32）→ 输出
   └─ 无 → 明确回答「教材里没有这部分内容」→ 可提示相关册次
```

### 7.2 提示词约束（硬要求）

- 只能使用检索到的原文片段，**不得使用模型自身知识补充教材内容**；
- 每句话后标注引用 `[三年级上册·数学·P32]`；
- 若片段不足以回答，输出固定拒答话术，**禁止推测**；
- 面向小学生：语言贴合年级，避免超纲术语；
- 讲解需举例，举例也必须出自教材或明确标注「（补充例子）」。

### 7.3 能力

| 能力 | 说明 | 依赖 |
| --- | --- | --- |
| 答疑 | 带原文引用 | 检索 + 生成 |
| 讲解 | 按课/知识点讲解，配教材例子 | 检索 + Section 定位 |
| 出题 | 单元练习、口算、听写、看拼音写词 | 按课生成 + 教材题型模板 |
| 批改 | 对照教材答案与知识点给反馈 | 需先抽取课后答案（V1） |

### 7.4 接口

```python
# agent/qa.py
def ask(question: str, scope: dict) -> Answer
# Answer: {text, citations: [(book_id, page_no, snippet)], refused: bool}

# agent/drill.py
def generate_drill(scope: dict, lesson: str, n: int = 10) -> list[Question]
def grade(answers: list[str], questions: list[Question]) -> list[Result]
```

### 7.5 命令行

```powershell
python -m agent_textbook ask "分数是什么意思" --grade 三年级 --subject 数学
python -m agent_textbook drill --grade 三年级 --subject 数学 --lesson 分数的初步认识
```

## 8. 存储布局

```
books/浙江杭州/小学/<学科>/<版本>/<年级>/*.pdf      采集产物（4.64 GB，94 册）
data/
├─ catalog.jsonl          平台全量书目（2925 条）
├─ downloads.jsonl        下载清单（109 条，含状态与直链）
├─ token.json             登录凭据（可选，勿提交）
├─ parsed/<book_id>.jsonl 解析产物：页文本 + 课结构
├─ index/
│  ├─ meta.sqlite3        chunks 元数据与过滤字段
│  ├─ vec.index           向量
│  └─ bm25.pkl            词项索引
├─ wiki/entries.jsonl     L2 词条（可选）
└─ eval/qa_set.jsonl      评测集
```

预期规模：文本层约 300–500 万字 → chunks 3–5 万条 → 向量 + 索引合计 **< 1 GB**。

## 9. 配置与依赖

`config.py` 需新增（V0 默认值）：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `PARSED_DIR` | `data/parsed` | 解析产物 |

| `OCR_ENABLED` / `OCR_ENGINE` | `True` / `rapidocr` | 扫描版开关 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `400` / `60` | 切块参数 |
| `LLM_BASE_URL` / `LLM_MODEL` | 环境变量 | 生成模型 |

新增依赖（追加到 `requirements.txt`，按需安装）：

```
pypdf>=4.0            # 文本层抽取
pdfplumber>=0.11      # 表格/版面辅助
rapidocr-onnxruntime  # 中文 OCR
bm25s>=0.2            # 关键词检索
sentence-transformers # 嵌入与重排（含 torch，体积大）

```

> `sentence-transformers` 会带入 torch（数 GB）。若不想装，可用 `onnxruntime` + 导出的 ONNX 模型替代。

## 10. 质量保障

### 10.1 评测集

`data/eval/qa_set.jsonl`，人工标注 200 题，两类各半：

```json
{"q": "分数的初步认识是哪一课？", "scope": {"grade":"三年级","subject":"数学","volume":"上册"},
 "answerable": true,  "expected_pages": [{"book_id":"...","page_no":67}], "ref_answer": "..."}
{"q": "小学教材里有微积分吗？", "scope": {...}, "answerable": false}
```

### 10.2 指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 命中率 | ≥ 85% | 可回答问题的 top-5 含正确页 |
| 拒绝正确率 | ≥ 95% | 不可回答问题时正确拒答（**比命中率更重要**） |
| 引用准确率 | ≥ 90% | 给出的页码确实包含该内容 |
| OCR 可用率 | 单列统计 | OCR 册的命中率单独统计，不混入整体 |

### 10.3 回归

```powershell
python -m agent_textbook eval --set data/eval/qa_set.jsonl
```

每次改动切块/检索/提示词后跑一次，指标回落即告警。

## 12. 实施计划

| 里程碑 | 内容 | 交付物 | 依赖 |
| --- | --- | --- | --- |
| **M0 基线** | `parse`：文本层抽取 + 目录解析 + `parsed/` 产出 | 能用 CLI 解析全量教材 | 已完成采集 |
| **M1 检索** | `index`：切块 + 向量 + BM25 + 元数据过滤 | `search` 命令可用 | M0 |
| **M2 问答** | `agent`：检索 + 生成 + 引用约束 + 拒答 | `ask` 命令可用 | M1 |
| **M3 评测** | 200 题评测集 + `eval` 回归 | 指标达标 | M2 |
| **M4 结构层** | 知识点清单 + 轻量本体 + 先修关系 | 导航类问答 | M3 |
| **M5 增强** | 扫描册 OCR 完善、出题批改、词条缓存 | 完整能力 | M4 |

**M0–M3 是必做主线**（对应选型文档 V0）；M4/M5 按实际收益决定是否投入。

## 13. 风险登记

| 风险 | 影响 | 对策 | 阶段 |
| --- | --- | --- | --- |
| 扫描版无文本层（科学/书法等 17 册） | 这些册检索不到 | OCR；解析阶段标记 `text_source`，评测单列 | M0 |
| 物理页码 ≠ 书上页码 | 引用页码错 | 建映射表；V0 注明"PDF 第 N 页" | M0 |
| 目录抽取失败 | 课的边界不准 | 三级回退策略；人工抽检 | M0 |
| 跨年级内容重复 | 串年级 | 检索强制元数据过滤 | M1 |
| LLM 用自身知识编造 | 误导孩子 | 提示词硬约束 + 拒答路径 + 评测拒绝正确率 | M2 |
| 换教材版本 | 答案过时 | 产物按版本隔离，换版重跑该版本 | 全阶段 |
| 依赖体积大（torch） | 安装困难 | 可选 ONNX 方案 | M1 |
