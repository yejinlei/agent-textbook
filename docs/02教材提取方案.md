# 02 教材提取方案

> 本文覆盖链路第二步 **解析（parse）**：把 `books/` 里的 PDF 变成可检索的结构化文本。
> 第一步下载见 `01教材下载.md`，整体架构见 `系统设计文档.md`。
>
> 对应代码：`src/agent_textbook/parse/`（`extract.py` / `vlm.py` / `pipeline.py` / `online.py` / `backfill.py`）

---

## 1. 定位与产物

| 项 | 值 |
| --- | --- |
| 输入 | `books/<地区>/<学段>/<学科>/<版本>/<年级>/*.pdf`（当前 94 册 / 8384 页） |
| 主产物 | `data/parsed/<book_id>.jsonl`——首行 meta，其后每页一行 |
| 中间产物 | `data/vlm_raw/<book_id>/<页号>.md`——VLM 原始输出，**兼作断点续跑缓存** |
| 扫描结果 | `data/scan.json`——每册页数、平均字符数、是否需要 VLM |

`jsonl` 每行自解释：

```jsonc
{"type":"meta","book_id":"…","subject":"科学","grade":"六年级","engine":"vlm",
 "pages":81,"chars":2,"figures":0,"empty_pages":75,"failed_pages":0,"online_pages":0}
{"type":"page","page_no":30,"printed_no":26,"chars":412,"source":"vlm",
 "has_pinyin":false,"figures":4,"fonts":[],"text":"3 形形色色的植物\n[图1] 描述：…"}
```

`source` 取值：`text_layer`（文本层）/ `vlm`（构建期 VLM）/ `vlm_online`（运行期在线补）/ `vlm_error`（失败留空）。

---

## 2. 引擎选型（实测对比）

| 候选 | 页脚 | 数学符号 | 拼音 | 结论 |
| --- | --- | --- | --- | --- |
| pypdf | 乱码 | 有多余空格 | 乱码 | 弃用 |
| **PyMuPDF** | **可读** | **保真（`24÷6×5`、`（3+5）×8`）** | 乱码（字体本身问题） | **通道 A 选定** |
| 本地 OCR（RapidOCR） | — | — | **声调全丢**（实测 `dirénniwóta`） | 弃用 |
| VLM | 可读 | 保真 | **能保住声调** | 通道 B 选定 |

> 拼音乱码是**字体自身的 ToUnicode 把带调元音映射成大写字母**（`tiQn` 实为 `tiān`），`fontTools` 也修不好——任何 PDF 库都还原不了。这是扫描册必须走 VLM 的根本原因。

---

## 3. 双通道与判定

```python
scan_book(pdf) → {"pages": 81, "avg_chars": 3.7, "need_vlm": True}
```

每册抽样 5 页，平均字符数 < `TEXT_LAYER_MIN_CHARS`(50) 判定为无文本层 → 走 VLM。

| 通道 | 适用 | 做法 | 成本 |
| --- | --- | --- | --- |
| A 文本层 | 78 册 / 7107 页 | span 级重建 + 拼音字体映射 | 数分钟跑完全部 |
| B VLM | 16 册 / 1277 页 | 渲染 200 dpi → 转录 + 插图描述 | 约 10 秒/页 |

实测无文本层的 16 册：**科学 8、艺术·美术 5、语文·书法练习指导 3**（美术、书法整册几乎零字符）。

---

## 4. 三个硬骨头

### 4.1 拼音乱码 → 按字体定位后映射

- 现象：`天/tiQn 地/dK 人/rRn`
- 根因：拼音用独立字体（名含 `Hanyu`），其 ToUnicode 把带调元音映射成大写字母
- 解法：**只对命中拼音字体的 span 做替换**（`fix_pinyin`），正文里的英语大写字母 `A`/`B` 不受影响
- 映射表：`parse/pinyin_map.json`，当前 20+ 条（`A→ǎ`、`Q→ā`、`S→à`、`G→ǒ`…）
- **待补**：仍有字符未覆盖，计划用 `pypinyin` 反查汉字读音自动推断并校验

附带发现：教材 PDF **全部无书签**，目录只能解析目录页文本；但页脚形如 `2 观察物体`（页码+课名）、页末独立数字 = 书上页码，可用于页→课对齐。

### 4.2 数学符号保真

实测 `24÷6×5`、`（3+5）×8` 文本层提取完好。因此数学册**优先走文本层、不 OCR**——符号 OCR 出错会直接教错孩子，是本项目最高风险项之一。

### 4.3 推理型模型返回空

`sensenova-6.8-flash-lite` 是推理型模型，token 被思考耗尽时只返回 `reasoning_content` 而没有 `content`，直接取 `content` 会 `KeyError`。

处理：`content` 缺失时回退 `reasoning_content`；`VLM_MAX_TOKENS` 提到 8192；仍为空则视为该页失败（留空待补）。

## 5. 插图理解纳入语料（★）

教材里的图**不是装饰**——数学的几何图形、线段图、统计图，科学的实验装置与观察对象，少了图就读不懂题。

做法：在**同一次 VLM 调用**里要求模型在图出现的位置插入描述，不额外增加 API 成本：

```
[图N] 描述：图中画了什么、有哪些标注与数据、说明了什么规律或关系
```

实测：

- 科学一册 58 页 → 27780 字、**137 处图描述**、54 页含图
- 科学六下第 30 页：4 处描述（苔藓树干、松果球果、水稻、蕨类羽状复叶）
- 第 16 页：把两张塔台设计图纸的标注（"上面：1个""侧面：2个"、三角形结构、底座塔身）还原成文字
- 美术六下第 10 页：9 处描述（梅兰竹菊的自然形态与笔墨技法、小女孩户外写生）

运行期拍照同样带图描述（几何图说清形状与已知条件）。

覆盖策略：扫描册**全部**带图描述；有文本层的册暂不单独跑图理解（7107 页全量不划算），后续按 **数学 > 科学 > 语文** 补（数学最依赖图）。

## 6. 学科差异化解析

| 学科 | 提取要求 | 现状 |
| --- | --- | --- |
| 语文 | 识字表/写字表**规则抽取**（拼音、笔顺、部首绝不能让 LLM 生成）；课文**整篇不切块**；习作只给支架与 rubric，禁止代写整篇 | Page 级已通；识字表/课文结构化抽取**待实现** |
| 数学 | 符号保真；区分例题与练习题；题目要带图形描述 | Page 级已通；例题/习题结构化**待实现** |
| 英语 | 单词表、对话 | 同上 |
| 科学/美术/书法 | 扫描册为主，靠 VLM + 插图描述 | 已通 |

> 语文与数学的"正确性"定义不同（字词可查表、习作只有 rubric、数学靠验算），因此上层 Guard 分 `strict` / `derivation` / `rubric` 三种模式——详见 `系统设计文档.md` §6.3。

**待实现**：目录解析 `parse_toc`、学科表抽取 `parse_subject_tables`（识字表/写字表/词语表、数学习题结构化）。当前产物只到 Page 粒度。

## 7. 两阶段提取：构建期批量 + 运行期在线

同一个 `VLMClient`，两个阶段共用，写的是**同一份产物**：

| 阶段 | 触发 | 输入 | 产物 |
| --- | --- | --- | --- |
| 构建期 | `parse` / `backfill` | 渲染的教材页 | `parsed/` + `vlm_raw/` |
| 运行期 | 孩子拍照提问、或问到没解析的页 | 上传图片 / 按需渲染 | 同上，**回填** |

```python
transcribe_photo(image)                  # 孩子拍的题目照片 → 文本（含图描述）
ensure_page(book_id, page_no)            # 本地没有就当场解析并回填
ensure_pages(book_id, page_nos)          # 批量：并发解析，只写一次盘
```

实测：拍照转录 13.3 秒出 298 字；美术六下第 10 页在线解析 20.3 秒 / 647 字 / 9 处图描述；**再次取同一页 0.00 秒**（命中回填）。

意义：**低价值册不必进构建期计划**。美术册整册预跑约 1.5 小时而答疑价值很低，改成"问到哪页补哪页"，单次 20 秒且补过永久复用。

## 8. 全量核对与补齐

```bash
python -m agent_textbook backfill --dry-run   # 只核对
python -m agent_textbook backfill             # 核对 + 补齐（幂等，可反复跑）
```

三类缺口：

| 缺口 | 判定 | 补法 |
| --- | --- | --- |
| 空壳册 | 缺页 > 50% | 整册 VLM，断点续跑 |
| 空洞页 | 有文本层册里的个别空页（整页插图、封面） | 单页 VLM，含图描述 |
| 失败页 | `source=vlm_error` | 单页重跑 |

首轮核对实测：**94 册 / 8384 页，待补 1155 页**（空壳册 14 册 1102 页 + 零散 53 页）。

两个健壮性设计：

- **断点续跑**：`vlm_raw/` 兼作缓存，整册跑到一半中断，重跑只补缺失页（实测中断在 63/94 页的册，重跑不浪费已完成页）
- **单页失败不拖垮整册**：单页报错只留空该页（记 `vlm_error` + 原因 + 自动重试 2 次），其余页照常落盘

## 9. 命令手册

```powershell
# 构建期
python -m agent_textbook parse --engine text_layer            # 全量走文本层（快）
python -m agent_textbook parse --engine vlm --need-vlm --workers 8   # 只补扫描册
python -m agent_textbook parse --engine vlm --subject 科学 --force
python -m agent_textbook parse-status                         # 册数/页数/通道分布

# 核对与补齐
python -m agent_textbook backfill --dry-run
python -m agent_textbook backfill --subject 语文·书法练习指导

# 运行期在线
python -m agent_textbook ensure-page <book_id> 10 12 --show   # 按需补指定页
python -m agent_textbook photo 作业题.jpg                      # 转录孩子拍的照片
```

环境变量：`VLM_API_KEY`（必填）、`VLM_MODEL`、`VLM_BASE_URL`、`VLM_DPI`、`VLM_WORKERS`、`VLM_MAX_TOKENS`。

## 10. 实测数据与已知问题

**成本与耗时**

| 项 | 实测 |
| --- | --- |
| 文本层 94 册 / 8384 页 | 数分钟 |
| VLM 8 并发 | 约 10 秒/页 |
| VLM 12 并发 | **反而 30 秒/页**（API 端排队）→ 固定 8 并发 |
| 全量补齐 1155 页 | 约 2.5–3 小时 |

**已知问题**

1. **拼音映射表未覆盖全**（`pinyin_map.json` 20+ 条，缺若干字符）→ 用 `pypinyin` 反查补全
2. **PDF 无书签**，目录页解析尚未实现 → 章节结构暂缺
3. **顺序敏感内容以文本层为准**：实测 VLM 转录识字表时把第 8 课排到第 6 课之前、把"语文园地一"提到汉字行前；两者冲突时记 `conflict` 供人工抽检
4. **数学公式页需人工抽检**：符号 OCR/转录出错会直接教错孩子，数学册优先文本层 + 公式页抽检
5. **有文本层册的插图尚未做图理解**（7107 页），按 数学 > 科学 > 语文 的优先级后续补
6. **美术册价值低**，已改为按需补（不进批量计划）
