### 8.11 记忆：课程进度与全学科画像（★）

Agent 必须知道两件事才能教：**孩子学到哪了**（位置）和**孩子会什么**（能力）。
前者是 `Progress`，后者是 `Profile`——两者都由记忆层提供。

#### 8.11.1 记忆分层（可审计、可修正）

| 层 | 内容 | 性质 |
| --- | --- | --- |
| **L0 原始** | 上传的卷子、对话记录 | 不可变，**可一键删除** |
| **L1 事件** | 结构化事件：日期 / 学科 / 课 / 题 / 对错 / 错因 | 追加写，可标注作废，**不可改** |
| **L2 画像** | 聚合结果：各科掌握度、强弱项、趋势 | **由 L1 重算**（`--rebuild`），不是增量累加 |
| **进度** | 当前位置（第几单元第几课）+ 来源与证据 | 可人工覆盖 |

三条硬原则：

1. **画像必须能重算**——增量累加会漂移，改一条历史记录就要能重导出；
2. **每个结论可追溯**——"这个薄弱点来自 10-06 卷子第 3 题"，不能是黑箱印象；
3. **家长可修正且优先**——"这题他其实会，那天是粗心"，人工标注优先于自动归因。

#### 8.11.2 ★ 进度推断：四源融合

| 来源 | 可靠度 | 说明 |
| --- | --- | --- |
| **交互推断**（★） | 中 → 高（累积后） | **从日常对话推断，用户什么都不用做** |
| 练习卷证据 | 高 | 卷子涉及的课/单元 → 实际学到哪（最直接） |
| 用户自定义 | 高 | 手动设"学到三上第 4 单元" |
| 时间预判 | 低（兜底） | 学期日历 + 周课时 + 单元数 → 估算"现在应该学到哪" |

**★ 交互推断：最省力的来源**

孩子在提问时就在透露进度，不需要额外设置、不需要上传卷子：

| 信号 | 例子 | 强度 |
| --- | --- | --- |
| 明确提到课 / 页 / 课文名 | "帮我听写第 3 课生字"、"第 12 页那题"、"《大青树下的小学》" | **强**（直接定位） |
| 提到知识点 / 题型 | "鸡兔同笼怎么做" | 中（可映射到课） |
| 作业求助 | "今天的作业是…" | 强 |
| 反复出现的主题 | 连续几天都在问同一主题 | 中（累积后变强） |
| 上下文线索 | "今天上了新课"、"明天要考试" | 弱（可追问确认） |

**技术基础已具备（实测）**——任意提问词都能定位到「册 + 起始页」：

| 提问词 | 实测定位 |
| --- | --- |
| 鸡兔同笼 | 数学四年级，P5 起（6 页） |
| 分数除法 | 数学六年级，P3 起 |
| 角的度量 | 数学四年级，P4 起 |
| 大青树下的小学 | 语文三年级，P3 起（第 1 课） |
| 小数点 | 四年级 P38 / **五年级 P12** |
| 平行四边形 | 四年级 P3 / **五年级 P3** |

**★ 交互与进度互相校准**：跨册命中天然有歧义（"小数点"是四下还是五上？）——
此时**用已知进度消歧**：已知在四年级就归到四下；若命中明显超前于已知进度
（三年级孩子问"分数除法"），说明是**超前学或预习**，提示确认，**不静默改进度**。

**推断规则（五条）**

1. **累积而非单次**：一次提问只记证据，多次一致才提升置信度；
2. **证据链可追溯**：记录"来自哪次对话的哪句话"（与 §8.11.1 可审计一致）；
3. **隐式推断不静默覆盖**：达阈值时提示一次"检测到你可能在学××，要更新进度吗？"；
4. **不打扰**：证据不足时保持沉默，绝不反复追问"你现在学到哪了"；
5. **与自定义冲突时以自定义为准**，仅提示确认。

**优先级：练习卷 / 自定义 > 交互推断 > 时间预判。**

**★ 两个进度必须分开**

| | 含义 | 用途 |
| --- | --- | --- |
| **教学进度** | 学校教到哪（**学到**哪） | 预习 = 当前课 + 1；**超纲拦截的上界** |
| **掌握进度** | 孩子真正**会**到哪 | 复习与提升计划的**下界** |

学得快 ≠ 会得多。**"学到第 8 课但只掌握到第 5 课"是最常见的情况**——
只用单一进度，会让复习计划建立在错误前提上（把没掌握的内容当成已会，跳过该补的）。

时间预判参数：每册单元数（可正则统计，语文约 6 个/册）、学期周数（约 20 周）、
周课时（可配置：语文 6 / 数学 5 / 英语 2 / 科学 1）。

> **当前能力边界**：定位到「册 + 页」已实测可行，**精确到"第几课"仍需目录**（§8.11.5 前置）。
> 目录抽取完成前，先用**页码**作代理坐标。

#### 8.11.3 ★ 进度直接约束 Guard（不只是"显示"）

`scope_guard` 要知道"学到哪"才能判断超纲——**没有进度，只能粗到"当前册"；有进度，能精确到"已学的课"**。

| 问题 | 无进度 | 有进度 |
| --- | --- | --- |
| 孩子问"什么是分数除法" | 查到教材里有 → 讲 | 进度在三年级（只学了分数初步认识）→ **"这是六年级内容，以后会学到"** |

预习 / 复习 / 测试的 `scope`（§8.10）同样依赖进度：**预习 = 当前课 + 1**，
**复习 = 已学范围**，**测试 = 只测已学**——三者都由进度决定。

#### 8.11.4 全学科画像

| 维度 | 内容 |
| --- | --- |
| **每学科** | 进度（第几单元第几课）、掌握度、强弱知识点、趋势（上升 / 下滑 / 停滞） |
| **跨学科** | 习惯（粗心率、完成度）、时间分配、学科均衡度 |
| **输出** | 家长周报 / 月报、雷达图；同时是 Agent 的决策依据（讲多深、推什么） |

画像的用途不是给家长看的报表，而是**让 Agent 每次回答都知道"这个孩子现在是什么水平"**。

#### 8.11.5 ★ 前置：先抽目录，否则进度没有坐标系

实证：当前 `parsed` 的 meta **没有目录/课表字段**（只有 `pages` / `chars`；单元只能靠正文正则统计，
且英语册 PEP 用 "Unit" 而非"第 X 单元"，正则数出 0 个）。

→ **要支持"课级进度"，必须先做目录抽取**（每册的「单元 → 课」清单）。
这也是 §8.9.1 课级字词要用识字表课号的原因——**课号是进度的天然坐标**。

```python
Progress:       learner, subject, book_id, unit_no, lesson_no,
                source: 练习卷|自定义|时间预判, confidence, updated_at, evidence[]
LearnerProfile: learner, grade, version,
                subjects{ subject: {teaching_progress, mastery_progress,   # ★ 双进度（8.11.2）
                                    mastery{kp_id: 0..1}, thinking_mastery{},
                                    strengths[], weaknesses[], trend} },
                habits{active_hours, session_len, preferred_form},   # 学习行为
                motivation{frustration_points[], liked_topics[]},    # ★ 只记可观测事实，不下定性标签
                prefs{verbosity, encouragement, default_form},
                source_events[], updated_at   # 每个结论都能追溯到 L1 事件
Event(L1):      date, type: 练习|问答|测试, scope, items[], result, source_id
```

工具：`get_progress` / `set_progress`（人工）/ `infer_progress`（时间预判）/
`get_profile` / `rebuild_profile`（重算）。

```powershell
python -m agent_textbook progress --set 数学=三上第4单元
python -m agent_textbook profile  --learner 小明 --rebuild
```

> **隐私**：进度与画像含未成年人学习数据，本地存储、可导出、**可一键删除**（同 §8.9.5）。

### 8.12 用户侧数据层（★ 教材之外的东西）

**与 §8.11 的分工**：§8.11 解决"**怎么记**"（L1 事件 / L2 画像 / 可重算可审计）；
本节解决"**记什么、存哪、归谁**"——即用户侧的完整资产清单。

**为什么必须单列**：本项目的数据分两类，性质完全不同——

| | 教材侧 | **用户侧** |
| --- | --- | --- |
| 内容 | 教材、课文、字词、题目、知识点 | 画像、全量交互、产物 |
| 来源 | 抽取自公开教材 | **用户使用过程中产生** |
| 可获取性 | **人人可得（公共品）** | **只有你有** |
| 丢失后果 | 重跑一遍即可 | **不可重建** |
| 归属 | 出版社 | **用户** |

→ **教材是公共品，用户数据才是唯一不可复制的资产。**
竞品能买到同样的教材、能抄架构，但抄不走一个孩子用了一学期积累的交互数据。
它还是**复利**：用得越久画像越准，冷启动的对手永远追不上。

#### 8.12.1 全量交互日志（raw，append-only）

**任何交互都要存**——不采样、不裁剪（成本实证见 §8.12.4）。

```
InteractionLog: id, ts, learner_id, subject, capability,
                user_input（原文）,  route（subject/capability/scope）,
                retrieved[]（book_id / page_no / kp_id）,   # ★ 引用了教材哪里
                tool_calls[], model, model_output,
                feedback（对/错/采纳/修改/重问）, latency_ms, app_version
```

**★ 存的关键是"引用"而不是"答案"**：记下这次回答引用了教材哪一页、哪个知识点，
日后才能回答"这个结论依据什么"、"为什么当时这么讲"——与 §8.11.1 的可审计同源。

#### 8.12.2 用户画像（derived，可从 raw 重算）

比 §8.11 的学情画像更完整，分六组：

| 组 | 内容 | 用途 |
| --- | --- | --- |
| 静态档案 | 年级、教材版本、可用时段 | 作用域与排期 |
| 进度（§8.11.2） | **教学进度 + 掌握进度（分开）** | 预习 / 复习 / 超纲拦截 |
| 学情 | 掌握度（知识点 × 思维方法）、错因分布、薄弱点 | 复习与出题 |
| **学习行为** | 学习时段与时长、会话节奏、提问方式、偏好形态（爱看图 / 爱做题 / 爱听讲） | 安排节奏与呈现方式 |
| **情感与动机** | 受挫点、坚持度、喜欢的主题、需要鼓励的时刻 | 措辞与"给台阶"的时机 |
| 偏好设置 | 讲解详略、要不要鼓励、默认输出形态 | 直接生效 |

**★ 两条硬约束**

1. **只记可观测事实与可修正结论，不下定性人格标签**——
   不写"注意力不集中""不聪明""厌学""数学不行"。这类标签一旦记下就会自我强化、
   无法证伪，且会被 Agent 当作前提（"他数学不行"→ 降低要求），伤害是静默的。
   要记的是："10-06 连续两次在鸡兔同笼卡住，第三次做对"（事实，可推翻）。
2. **画像用户可看、可改、可删**——不是黑箱评分。

#### 8.12.3 产物

作文、生成的 PPT / 动画 / 音频、批改记录、练习卷解析——与交互日志关联存储，
**可回溯、可重放**（家长能回看"这道题当时是怎么讲的"）。

#### 8.12.4 成本实证：全量存是零成本的

| 项 | 实测 / 估算 |
| --- | --- |
| 教材侧（94 册全文 parsed） | **7.8 MB** |
| 用户侧（每天 20 轮 × 每轮约 1.5 KB） | 约 **30 KB/天 → 11 MB/年**（含完整模型输出约 30 MB/年） |

→ **一年的全量交互数据，只有教材数据的两三倍，几十 MB。** 本地存储毫无压力，
因此**不需要采样、不需要裁剪、不需要"只保留最近 100 条"**。

对比：云端产品必须为成本裁剪日志、用采样统计用户行为。
**全量保留 + 数据不出本机**，是本地架构带来的结构性优势，不只是隐私姿态。

#### 8.12.5 隐私与合规（★ 卖点，不是附加项）

| 要求 | 做法 |
| --- | --- |
| 本地优先 | 全部存 `data/users/<learner>/`，**不上云** |
| 儿童个人信息 | 涉未成年人学习数据，按《儿童个人信息网络保护规定》：最小化收集、监护人可查阅 / 更正 / 删除 |
| 可导出 | 一键导出 JSON / Markdown（换设备、给老师看） |
| 可删除 | 一键删除**某条记录 / 某个孩子 / 全部** |
| 明文可审计 | 画像为 Markdown，家长可直接打开查看和修改（同 §8.11.1） |
| 多孩隔离 | `learner_id` 分隔，互不串数据 |

**竞品对照**：学习机与 AI 陪练把孩子的**语音、错题、作文全部上传云端**（用于家长 App 与模型训练）。
"孩子的语音与作文不出本机"是云端产品**架构上做不到**的差异——它同时是隐私卖点与合规优势。

#### 8.12.6 冷启动

新用户画像空白，三条路：

1. **年级默认值起步**——宁可按年级**下限**估计，不夸大水平；
2. **快速摸底**：5–10 分钟自适应小测（按年级出题，答对往上、答错往下），先建粗略掌握度；
3. **前几次交互只观察、不断言**——证据够了再提示确认（§8.11.2 推断规则）。

→ 冷启动期**不装作很了解孩子**，明确说"我还不太了解你，我们先聊聊/先做几道题"。
  这比"一开始就给一堆看似精准的判断"更可信，也避免了错误画像的自我强化。

```powershell
python -m agent_textbook user  --add 小明 --grade 三 --version 人教
python -m agent_textbook log   --learner 小明 --export out.json
python -m agent_textbook user  --delete 小明            # 一键删除
```

#### 8.12.7 ★ 输入与产出的全量存储（规格）

**原则：原文全留、过程全留、不裁剪。**

**（1）输入侧——存原文，不存摘要**

| 输入 | 存什么 |
| --- | --- |
| 文字提问 | **原文**（不改写、不摘要、不"规范化"） |
| 上传作业 / 练习卷 | 原图（压缩后）+ VLM 提取结果 |
| 语音（V1） | **ASR 文本留，原始音频默认不留** |
| 手写作答 | 图片 + 识别结果 |
| 用户改正反馈 | 原文 + 时间戳（人工标注优先于自动归因，§8.11.1） |

**★ 为什么要原文而非摘要**：摘要不可逆，且会丢掉"**孩子原话是怎么问的**"——
提问方式本身就是画像原料（§8.12.2 学习行为）。压缩成"问了分数"，
就再也看不出他是真不懂、还是表达不清、还是只想要答案。

**（2）输出侧——存过程，不只存结果**

| 层 | 内容 |
| --- | --- |
| 检索证据 | 命中教材哪一页 / 哪个知识点（**带引用**） |
| 中间草稿 | Teacher 初稿 |
| **Guard 结果** | 通过 / 打回 + **打回原因** |
| 终稿 | 实际呈现给用户的内容 |
| 多形态产物 | 动画 / PPT / 音频 / HTML（文件 + 元数据） |

**★ 连"被打回的版本"都要存**：它记录了模型在这个孩子身上容易犯什么错
（超纲？编造？题型不对？）——既是审计依据，也是改进 prompt 与 Guard 规则的**唯一素材**。
**只存终稿，就永远看不到失败模式。**

**（3）体积实证与保留策略**（★ 修正 §8.12.4 的乐观估算）

| 项 | 实测 / 估算 |
| --- | --- |
| 文本（输入 + 证据 + 草稿 + Guard + 终稿） | 约 **40–70 MB/年**（实测：单页文本产物 1.1 KB、单册 parsed 85 KB） |
| 图片（作业 / 练习卷） | 扫描页约 200 KB/页（实测教材 PDF 11–25 MB/册）→ 压缩后年增数十 MB |
| **音频** | 约 1 MB/分钟 → 每天 5 分钟 ≈ **1.5 GB/年** ← **真正的大头** |

| 类别 | 策略 |
| --- | --- |
| 文本 | **全留，不设上限** |
| 图片 | 压缩后保留；可选"只留 VLM 提取结果、不留原图" |
| 音频 | **默认只留 ASR 文本，原始音频默认关**（体积大 + 涉生物特征） |
| 视频 / 动画 | **不存大文件**，只留生成参数与 `ContentPlan` |

→ **用"可重放"替代"存大文件"**：参数与 `ContentPlan` 在，产物随时能重新生成，
不必为了体积牺牲完整性。

**（4）★ 全量交互 = 最好的评测集**

真实日志解决了评测集最难的问题——**题目从哪来**：

| | 人工造评测集 | **真实日志** |
| --- | --- | --- |
| 分布 | 靠猜 | **真实**（孩子实际问什么） |
| 数量 | 有限（200 题） | **持续增长** |
| 维护 | 人工 | 零 |

→ 换模型 / 改 prompt 后，用历史真实问题**重放**（replay）对比新旧输出，
就是 §11 的回归门。**这是"存储"从成本变成资产的转折点。**

**（5）存储实现**

```
data/users/<learner>/
  log/2026-10.jsonl       # append-only 事件流（输入/证据/草稿/Guard/终稿）
  artifacts/2026-10/      # 图片、PPT、动画、音频
  index.sqlite3           # 可查询：按学科 / 日期 / 知识点 / 对错
```

- **JSONL append-only**：不改历史，只追加——**可审计的前提**（与 §8.11.1 同源）
- **SQLite 索引**：支撑"找出小明所有关于分数的错题"这类查询
- 画像 `profile.md` 由 log 重算（`--rebuild`），单向依赖，不会漂移
