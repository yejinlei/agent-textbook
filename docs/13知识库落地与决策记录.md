## 7. 落地路线

按"先跑通、再加料"的顺序，每层都可独立交付：

| 阶段 | 内容 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| **V0 跑通** | PDF 文本层抽取 + 扫描版 OCR → 按课/页切块 → BM25 + 向量混合检索 → 元数据过滤 → **决策层最小集 Router / Retriever / Guard（§5.2）** → 带引用回答 | 能问答，答案带册次页码 | 200 题评测集上：有答案的问题命中率 ≥ 85%，无依据时正确拒答 ≥ 95% |
| **V1 结构** | 目录树抽取 → 单元/课/知识点清单 → 轻量本体与先修关系 | 能按"三年级上册第三单元"精确定位；能查"分数在哪些册出现" | 导航类问题准确率 ≥ 90% |
| **V1.5 展现** | 动画模板（分数 / 线段图）+ 音频 TTS + HTML 交互 | 数学题能出动画、英语能跟读 | 动画数值与教材例题一致（抽检 100%）；**无模型自由绘制** |
| **V2 词条** | 高频知识点 LLM 编译成词条（带引用） | 热点问题延迟与成本下降 | 词条与原文一致性抽检准确率 ≥ 95% |
| **V3 增强** | 图文关联（插图/表格）、公式处理、跨册知识演进视图 | 能回答"看图说一说"这类题目 | 按需 |

**V0 必须完整做完并评测达标，再动 V1。** 理由：V0 是唯一保证溯源性的层，它决定了整个系统的可信度上限。

## 8. 技术选型建议

| 环节 | 建议 | 理由 |
| --- | --- | --- |
| 文本抽取 | `pypdf` / `pdfplumber` | 文本层 PDF（语文/数学/英语/道法）直接抽，快且准 |
| OCR | `RapidOCR` / `PaddleOCR`（中文） | 科学、书法等高清图版需 OCR，CPU 可跑 |
| 切分 | 按"课"为主，页为辅；块 300–500 字，overlap 50–80 字 | 教材的课是天然语义单位，比滑动窗口更贴合 |
| 嵌入 | `bge-small-zh` / `bge-m3`（384–1024 维） | 中文效果好，CPU 可跑，3–5 万块几十分钟 |
| 关键词检索 | `bm25s` / `rank_bm25` | 教材专有名词多（"分数的初步认识"），字面匹配非常重要 |
| 融合 | RRF（倒数排名融合） | 无需调权，简单稳健；向量管语义，BM25 管精确术语 |
| 重排 | `bge-reranker-v2-m3`（仅对 top-20） | CPU 上较慢，只对小候选集用 |
| 存储 | SQLite（元数据 + BM25）+ `sqlite-vec` / `faiss`（向量） | 单机、零运维、够用；数据规模 < 1GB |
| 元数据过滤 | 学段 / 地区 / 学科 / 版本 / 年级 / 册次 / 单元 / 课 / 页码 | **过滤先于检索**：先框定"孩子当前学哪一册"，再检索 |
| 生成 | 任意中文 LLM（API 或本地） | 提示词强制引用格式，禁止无依据回答 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| OCR 错误（尤其公式、汉字） | 科学/书法册答案不可靠 | OCR 低置信度标记；教材术语词典后校验；公式单独处理（保留图片 + 人工规则） |
| 扫描版无文本层 | 部分册检索不到 | 解析阶段输出 `text_source=ocr/text_layer` 标记，评测时单列统计 |
| 插图与图表 | 教材大量"看图回答"题型 | V0 只入图注与图周围文本；多模态留到 V3 |
| 知识点跨册重复（螺旋上升） | 回答可能引用错年级 | 检索默认限定当前年级册次，跨册结果需显式标注"四年级下册也讲过" |
| Wiki 与原文不一致 | 误导 | Wiki 仅作缓存，强制带引用页码，支持一键回原文；原文更新即失效 |
| 换教材版本 | 全部失效 | 采集层已按 `版本` 隔离目录；解析/入库产物按版本分库，换版只重跑对应版本 |
| **教辅说法与教材不一致** | 孩子学到"教材没写的版本" | 教材优先（core > aid > ext）；冲突记 `conflict` 抽检；引用强制带 tier 标签 |
| **教辅超纲**（三年级教辅讲四年级内容） | 讲超纲内容 | `scope_guard` 覆盖教辅层，超出当前册要素范围标"课外选学" |
| **课外书无锚点** | 跑题、喧宾夺主 | 无锚点不入库；只挂语文要素 / 单元主题 / 推荐书目锚点 |
| 教辅与课外书版权 | 合规风险 | 仅本地个人使用，不随产物分发，不入库共享 |

## 10. 决策记录（ADR 摘要）

**决策**：RAG 原文层为永久底座 + 目录树作图谱骨架 + 轻量本体（≤6 种关系）+ 按需 LLM-wiki 缓存。

**理由**：可溯源是硬约束，只有原文层能满足；教材自带高质量层级结构，自动抽取图谱性价比为负；语料规模小（约 500 万字），预编译收益有限而风险实在。

**放弃的方案**：
- 全量知识图谱 + 完整本体工程 —— 抽取质量风险高、换版成本大，本场景多数需求可用元数据过滤满足。
- 纯 LLM-wiki —— 破坏可溯源性，覆盖率不可控，编译期幻觉无法在查询时发现。

**何时重新评估**：
- 语料扩到全学段（小学+初中+高中，约 3000 册、上亿字）时，重估图谱的必要性；
- 多跳类问题（"学会 X 之前必须先掌握哪些"）占比超过 15% 时，加强先修关系；
- 在线成本成为瓶颈且热点足够集中时，扩大 wiki 覆盖范围。
