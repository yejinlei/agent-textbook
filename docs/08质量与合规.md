## 10. 存储布局

```
books/浙江杭州/小学/<学科>/<版本>/<年级>/*.pdf      采集产物（4.64 GB，94 册）
data/
├─ catalog.jsonl / downloads.jsonl                 书目与下载清单（复现契约）
├─ token.json                                      登录凭据（不入库）
├─ scan.json                                       全册扫描：页数、文本层判定、通道选择
├─ parsed/<book_id>.jsonl                          页文本 + 课结构 + 学科表（每页带 source 字段）
├─ vlm_raw/<book_id>/<page_no>.md                  VLM 原始输出（可回溯、换模型后可 diff）
├─ index/
│  ├─ v1/ v2/ …                                    版本化索引，指针切换
│  │  ├─ meta.sqlite3     chunks / pages / lesson_texts / words / problems
│  │  ├─ vec.index        向量（不含课文整篇与字词表）
│  │  └─ bm25.pkl         词项索引
│  └─ current -> v2
├─ memory/<learner>/
│  ├─ events/<surface>/<date>.jsonl                L1 事件轨迹
│  └─ profile.md                                   L2 学情画像（可读可改）
├─ wiki/entries.jsonl                              L2 词条（可选）
└─ eval/
   ├─ retrieval.jsonl                              检索评测（query + gold）
   ├─ chinese_words.jsonl / chinese_reading.jsonl / chinese_writing.jsonl
   └─ math_solve.jsonl / math_mental.jsonl
```

预期规模：文本层约 300–500 万字 → chunks 3–5 万条 → 索引合计 **< 1 GB**。

## 11. 质量保障

### 11.1 检索评测（借鉴 DeepTutor `kb eval`）

`data/eval/retrieval.jsonl`，每行 `{"query", "scope", "gold": [片段], "answerable"}`，指标：**Recall@k / Precision@k / nDCG@k / MRR / MAP / Hit@k**。

**指标是排序的纯函数，不用模型当裁判** —— 结果可复现、可 diff。保存 baseline 后，任何切块/嵌入/重排改动都跑一遍，回落即告警。

### 11.2 分学科端到端评测

| 学科·能力 | 指标 | 目标 | 判定方式 |
| --- | --- | --- | --- |
| 语文·字词 | 查表准确率 | ≥ 99% | **确定性**（对表里答案） |
| 语文·阅读理解 | 答案定位准确率 | ≥ 85% | 人工标注段落 |
| 语文·习作 | rubric 评分与教师评分相关性 | ≥ 0.7 | 人工抽评 |
| 数学·概念讲解 | 引用准确率 | ≥ 90% | strict 自动 + 抽检 |
| 数学·解题 | 最终答案正确率 / 步骤完整率 | ≥ 90% / ≥ 85% | **答案确定性验算**，步骤人工抽检 |
| 数学·错因 | 归因准确率 | ≥ 80% | 人工标注 |
| 数学·口算 | 生成合法性与判分正确率 | 100% | 确定性 |
| 通用·拒答 | 不可答问题的拒答正确率 | ≥ 95% | **最重要** |
| 通用·Guard | 漏检率 / 误杀率 | 漏检 ≤ 3% / 误杀 ≤ 10% | 人工标注集 |

### 11.3 多 Agent 专项评测

| 对象 | 测什么 |
| --- | --- |
| Router | 意图分类准确率、**学科+能力**抽取准确率 |
| Planner | 查询改写后召回是否提升；检索方式选择是否正确（查表 vs 语义） |
| Teacher | 年级适配度（人工 1–5 分）、引用完整率 |
| Guard | 三模式各自的漏检率与误杀率 |
| Quizzer | 题目与课匹配度、答案正确性、出处正确率 |
| Grader | 判分准确率（应等于确定性判定）、错因归因准确率 |

Guard 的**漏检率**是最需要盯的指标——它一旦放水，整个系统的可信度就塌了。

### 11.4 回归

```powershell
python -m agent_textbook eval --set data/eval/retrieval.jsonl --baseline baseline.json
python -m agent_textbook eval --subject 语文 --capability 字词
python -m agent_textbook eval --subject 数学 --capability 解题
```

## 12. 配置与依赖

`config.py` 需新增：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `PARSED_DIR` / `INDEX_DIR` / `MEMORY_DIR` | `data/parsed` / `data/index` / `data/memory` | 产物目录 |
| `EMBED_MODEL` | `bge-small-zh-v1.5` | CPU 可跑 |
| `RERANK_MODEL` | `bge-reranker-v2-m3` | 仅对 top-20 |
| `PARSE_ENGINE` | `auto` | `text_layer` / `vlm` / `ocr` |
| `PARSE_CHANNELS` | `("text", "vlm")` | 通道组合；`"vlm"` 单独用于无文本层册 |
| `PINYIN_FONT_PATTERN` | `Hanyu` | 拼音字体名特征（命中的 span 才做映射修复） |
| `VLM_BASE_URL` / `VLM_MODEL` / `VLM_API_KEY` | 环境变量 | **构建期与运行期共用**的多模态通道 |
| `VLM_DPI` / `VLM_WORKERS` | `200` / `8` | 渲染清晰度与并发 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `400` / `60` | 切块参数 |
| `LLM_MAIN` / `LLM_LIGHT` | 环境变量 | 主模型（Teacher）与轻量模型（Router/Planner/Guard） |
| `AGENT_MAX_ROUNDS` | `6` | Agent 循环轮次上限 |
| `GUARD_MODE` | `auto` | `auto`（按学科 Profile）/ 强制 `strict`/`derivation`/`rubric` |
| `TTS_ENABLED` | `false` | V1：语文听写与朗读 |

新增依赖（追加到 `requirements.txt`）：

```
pymupdf>=1.24         # 文本层抽取（主力：可拿到 span 级字体，才能修拼音）
pypinyin>=0.50        # 反查汉字读音，推断/校验拼音映射
fontTools>=4.0        # 字体编码解析
pdfplumber>=0.11      # 表格/版面辅助（抽字词表用）
rapidocr-onnxruntime  # 离线兜底 OCR（非主力：拼音不可用）
bm25s>=0.2            # 关键词检索
sentence-transformers # 嵌入与重排（含 torch，体积大）
sqlite-vec            # 向量存储（或用 faiss-cpu）
```

> `sentence-transformers` 会带入 torch（数 GB）。若不想装，可用 `onnxruntime` + ONNX 导出模型替代。

## 13. 性能与成本预算

| 环节 | 规模 | CPU 预估 |
| --- | --- | --- |
| 文本层抽取（通道 A） | 78 册 7107 页 | 数分钟 |
| VLM 抽取（通道 B） | 16 册 1277 页，并发 8 | 50–60 分钟 |
| 运行时按需 VLM | 单页 / 单张照片 | 14–30 s |
| 学科表抽取 | 字词表数千条、数学题数千道 | 数分钟 |
| 切块 + 嵌入 | 3–5 万块 | 几十分钟（bge-small） |
| 字词查询 / 口算练习 | 单次 | **毫秒级，0 次 LLM** |
| 普通问答 | 3 次 LLM 调用 | 取决于模型；本地小模型数秒 |
| 数学解题 | 4–5 次 LLM 调用（含验算） | 略高于普通问答 |
| 磁盘 | 教材 4.64 GB + 索引 < 1 GB | — |

## 15. 风险登记

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 扫描版无文本层（科学/美术/书法 16 册 1277 页） | 这些册检索不到 | **VLM 通道**提取；标记 `source=vlm`，评测单列 |
| **VLM 重排原文顺序** | 识字表按课归类、课文段落错乱 | 顺序敏感内容一律以文本层为准；VLM 只作语义补充；冲突写 `conflict` 待抽检 |
| VLM 输出不稳定（换模型 / 改提示词） | 语料不可复现 | 保存 `data/vlm_raw/` 与模型版本，可 diff 回溯 |
| 物理页码 ≠ 书上页码 | 引用页码错 | 建映射表；V0 注明"PDF 第 N 页" |
| **数学符号 OCR 出错** | **教错孩子** | 数学册优先文本层；OCR 册人工抽检公式页；`symbols_preserved` 标记 |
| **语文课文切块破坏语境** | 阅读理解答不准 | 课文整篇另存不切块（§7.1） |
| **字词让 LLM 生成** | 编造拼音/笔顺 | 强制规则抽取 + 查表返回，字词路径禁用 LLM 生成 |
| **作文被 strict Guard 卡死** | 功能不可用 | Guard 三模式，创作类走 rubric（§9.2） |
| **代写作文/作业** | 对孩子有害 | 只给支架与片段示范，产品层面禁止输出完整成品 |
| LLM 用自身知识编造 | 误导孩子 | Teacher 引用约束 + Guard 独立校验 + 拒答路径 |
| 多 Agent 放大延迟与成本 | 体验差 | 小模型下沉、规则替代 LLM、缓存、轮次上限 |
| 多 Agent 角色间不一致 | 同一问题两次答案不同 | 共享 sticky 上下文与同一批检索片段；Teacher 是唯一事实讲述者 |
| Guard 过严导致误杀 | 正常讲解被拒 | 调阈值；漏检率/误杀率双指标监控 |
| 换教材版本 | 答案过时 | 产物按版本隔离；索引版本化 + 单册重跑 |
| 依赖体积大（torch） | 安装困难 | 可选 ONNX 方案 |

## 16. 合规

教材版权归国家中小学智慧教育平台及相关权利人所有。本系统所有产物（解析文本、索引、词条、学情）仅限**个人学习与家庭辅导**使用，不得分发、公开部署或商用。

**★ 练习卷的额外约束**：练习卷含未成年人真实数据（姓名、班级、笔迹、成绩），与公开教材性质不同：

1. **默认本地处理**——VLM 优先本地模型（Ollama + Qwen2-VL / InternVL）；
2. 送云端 API 前必须**显式提示并征得确认**，不得无感上传；
3. 上传前提示遮盖姓名与班级（或自动裁切卷头）；
4. 卷面与诊断结果**本地存储、支持一键删除**，不进入任何训练集或日志。

> 这是全系统唯一涉及未成年人个人信息的环节。**宁可识别率略低，也不默认外传。**

调研参考：DeepTutor（HKUDS，Apache-2.0）、OpenMAIC（清华 THU-MAIC）。本文的设计取舍为本项目的独立判断，二者仅作为架构参照。
